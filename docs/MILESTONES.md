# Phase One milestone report

The initial implementation spans all seven milestones at MVP/prototype depth. Phase One acceptance is **partially validated**, not signed off: real Spotify, physical device-change and broader musical-accuracy checks remain open. No Phase Two artistic renderer was built.

| Milestone | Implemented | Tests and results at milestone | Known issues / performance | Recommended next step |
|---|---|---|---|---|
| 1 — Repository / architecture | Empty workspace initialized as local Git repository; source abstraction, immutable schema, bounded queues and pub/sub, dependency decisions | 3 tests passed | No hardware claims at this stage | Connect real system loopback |
| 2 — System capture | WASAPI device listing, default/specific output selection, start/stop, clock segments, waiting/recovery states; common file source | 6 tests passed; five-second live probe received 480 blocks, nonzero activity, no drops | G6 detected at 48 kHz / 8 channels; physical hotplug untested | Add causal mixed-audio DSP |
| 3 — Immediate analysis | Energy, short-term RMS loudness, spectral moments/contrast, band powers, flux, onset/transient candidates, tempo history, silence, adaptive intensity | 13 tests passed; known tones at four rates, stereo cancellation resistance, silence and pulse timing/tempo | Candidate identities and confidence are heuristic; no LUFS or phase-locked beat tracker | Connect publication and session logging |
| 4 — Streaming / logs | In-process event bus; async JSONL/CSV/manifest/summary/performance/error package; replay preserves audio timestamps | 15 tests passed; 12-second live full pipeline: 593 frames, no drops, DSP p95 1.87 ms | Subscribers/loggers may drop oldest messages under overload; counters expose loss | Validate desktop controls |
| 5 — Control center | Source/settings controls, start/stop, input/transient meters, tempo/events, diagnostics, session folder and log export | Actual Windows UI start/live display/stop verified; session completed, no UI/audio drops | Diagnostic UI only; source selection disabled during a run | Evaluate per-process capture |
| 6 — Application capture | .NET 9 / NAudio helper using process-tree loopback; read-only sessions across active outputs; PID creation-time checks; same-executable restart search; explicit system fallback | 20 tests passed; native build zero warnings/errors; browser capture and silent-target/system-mix exclusion comparison passed | Spotify and real restart untested; ambiguous restarts wait; all tabs of a selected browser process tree are included | Add optional delayed analysis |
| 7 — Advanced prototype | Separate bounded worker, two-second in-memory chunks, CPU median HPSS characteristics, original interval timestamps, plugin callable interface | 22 tests passed at milestone; seven live jobs around 60 ms each; no Tier A drops | Does not produce instrument stems; Demucs researched but not installed/benchmarked; no fabricated vocal activity | Validate musical corpus and benchmark a selected stem model outside Tier A |

Subsequent hardening added opt-in duration-capped debug recording, startup-error cleanup, shared source origin, recovery/format-change/overload tests, a Qt runtime smoke test, reproducible CPU benchmark and a two-minute live capture. Final suite: **30 passing tests**, clean lint/format checks and native build. See [validation](VALIDATION.md) for measured figures and remaining hardware checks. Local Git history contains coherent commits for the milestones; no remote repository or publication was created.

## Next development increment

Keep the visualization engine out of scope until capture reliability and schema behavior are exercised on real music. First run Spotify through both system and process capture, verify paused/quiet periods and app restart, then physically switch/disconnect outputs with user participation. Build an annotated fixture corpus and measure musical detection errors. For advanced work, benchmark a separately installed CPU Demucs environment on short authorized excerpts, measuring realtime factor, RAM, chunk boundaries and timestamp alignment before considering any default-enabled model. Retain the current lightweight HPSS option as a clearly labeled spectral diagnostic.
